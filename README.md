# 최종_진짜최종

**원래 원고와 고친 원고를 나란히 두고, 문단마다 반영할 부분을 선택합니다.**

「보고서_최종.hwp」와 「보고서_최종_진짜최종.hwp」가 같은 폴더에 있는데 둘이 뭐가 다른지는 아무도 모르는 상황을 위해 만들었습니다.

업로드한 문서는 이 브라우저 밖으로 나가지 않습니다. 사용자 기기 자체(로컬 환경)에서 데이터를 처리합니다.

## 사용 방법

원문과 수정본을 하나씩 올립니다. 파일이 없으면 글을 그냥 붙여넣어도 됩니다.

바뀐 문단이 좌우로 놓이고, 달라진 글자에 색이 들어갑니다. 문단마다 「원문 유지」와 「수정 채택」 중 하나를 누릅니다. 안 누른 문단은 원문으로 남습니다.

왼쪽 목록은 원고를 **단락**으로 끊어 보여 줍니다. 빈 줄 하나로 묶인 문단 덩어리를 말합니다. `Alt + ←/→` 로 단락을, `Alt + ↑/↓` 로 변경을 건너뜁니다.

다 골랐으면 내려받습니다. 위쪽 띠에서 밝은 화면과 어두운 화면을 고르고, 비교 중에는 본문 글자 크기를 조절할 수 있습니다.

### 작업 가능 확장자

| | 읽기 | 저장 |
|---|---|---|
| **HWPX** | ○ | ○ (서식 유지) |
| **DOCX** | ○ | ○ (서식 유지) |
| **TXT** | ○ | ○ |
| 붙여넣은 글 | ○ | TXT·DOCX 로 |
| `.hwp` `.doc` | ✕ | ✕ |

옛 `.hwp` 는 한글에서 **다른 이름으로 저장 → HWPX** 로 한 번 바꿔 주세요. `.doc` 는 워드에서 `.docx` 로 저장하면 됩니다.

HWPX와 DOCX는 **서로 바꿔서도** 저장할 수 있습니다. HWPX 두 벌을 비교해 놓고 DOCX로 내려받아도 되고, 붙여넣은 글을 DOCX로 뽑아도 됩니다.

### 서식 보존 범위

저장할 때 문서를 새로 만들지 않습니다. 올린 파일을 그대로 복사한 뒤, 고치기로 한 문단의 글자만 바꿔 넣습니다.

고친 문단 안에서 일부만 다르게 준 서식은 문단 첫 글자의 서식으로 통일됩니다.

표는 문단이 아니라서, 저장하면 틀로 쓴 원고의 표 구성을 그대로 따릅니다. 두 원고의 표 개수가 다르면 비교를 열 때 알려 줍니다.

HWPX를 올려놓고 DOCX로 내려받을 경우, 본떠 올 DOCX가 없어 기본 서식의 새 문서로 나갑니다.

### 단락 나누기

빈 줄 하나가 단락을 나눕니다.

표 하나는 통째로 단락 하나입니다.

## 줄바꿈 정리

PDF나 웹에서 복사한 글은 한 문단이 대여섯 줄로 쪼개져 붙습니다. 이대로 비교하면 줄이 어디서 끊겼는지가 죄다 「변경」으로 잡혀서 아무것도 안 보입니다. 붙여넣기 화면의 「줄바꿈 정리」를 사용하여 문장 도중에 끊긴 줄을 도로 이어 붙입니다.

문장부호로 끝난 줄, 목록 기호(`-` `1.` `가)` `①` `제3조`)로 시작하는 줄, 따옴표로 여는 대사는 그대로 둡니다.

## 검토표

「검토표 ↓」를 누르면 바뀐 문단만 모아 CSV로 나옵니다. 단락, 단락 첫 문장, 변경 번호, 종류, 원문, 수정본, 고른 결과가 한 줄씩 들어갑니다.

무엇을 왜 그렇게 골랐는지 추적하거나 로컬 파일로 비교할 수 있습니다. 

## 자료 처리 및 저장

읽기·비교·저장은 모두 이 브라우저 안에서 이루어집니다.

선택한 내용은 이 브라우저에만 남습니다. 같은 원고 두 벌을 다시 올리면 선택이 되살아납니다. 원고 본문은 보관하지 않으므로 파일은 다시 올려야 합니다. 기록은 이 주소와 이 브라우저에만 있고, 사이트 데이터를 지우면 같이 사라집니다.

**중요한 원고는 파일로 내려받아 두세요.**

## 개발

Node 24가 필요합니다. 설치돼 있으면 `최종_진짜최종 열기.bat` 을 더블클릭해 내 PC에서 바로 열 수 있습니다.

<details>
<summary>명령어와 안쪽 구조</summary>

```sh
npm ci
npm run dev     # 개발 서버
npm test
npm run build   # dist/ 가 그대로 완성된 사이트
```

빌드 결과는 어느 하위 주소에 올려도 열리도록 경로를 상대로 잡아 두었습니다.

테스트는 110개입니다. 문서 읽기·쓰기와 비교는 한글과 워드가 실제로 만든 `samples/` 파일로 검증하고, 화면은 [linkedom](https://github.com/WebReflection/linkedom) 위에서 브라우저 없이 돌립니다.

| 파일 | 맡은 일 |
|---|---|
| `src/core/xml-spans.js` | XML을 문자열로 두고 필요한 구간 위치만 찾기 |
| `src/core/zip-doc.js` | HWPX·DOCX 읽고 쓰기. 바뀐 문단만 갈아 끼우기 |
| `src/core/docx-blank.js` | DOCX 원고가 없을 때 쓸 빈 문서 짓기 |
| `src/core/txt.js` | TXT 읽고 쓰기 (UTF-8·UTF-16·CP949) |
| `src/core/compare.js` | 문단 맞추기, 변경 묶기, 고른 대로 합치기 |
| `src/core/cleanup.js` | 끊긴 줄 다시 잇기 |
| `src/core/csv.js` | 검토표 만들기 |
| `src/ui/` | 메인 화면과 작업 화면 |

XML을 트리로 읽어 다시 써 내보내지 않습니다. 그렇게 하면 속성 차례와 네임스페이스 표기가 미묘하게 달라져서, 한글이나 워드가 파일을 아예 거부하는 일이 생깁니다. 원본 문자열은 손대지 않고 바뀐 문단의 글자만 잘라 끼웁니다.

```sh
node scripts/probe.mjs "samples/파일.hwpx"      # 문단이 어떻게 읽히는지 보기
node scripts/roundtrip.mjs "samples/파일.hwpx"  # 고쳐 쓴 파일을 만들어 직접 열어 보기
```

`samples/` 는 한글과 워드가 실제로 만든 파일입니다. 손으로 지어낸 XML로 시험하면 실물에서 깨지기 쉽습니다.

## 예문 출처

예문은 둘입니다. 「예문 보기」는 글을 다듬는 쪽을, 「설문 보기」는 표가 든 문서를 보여 줍니다.

「예문 보기」는 윤동주의 산문 **「달을 쏘다」**를 씁니다. 1939년 조선일보 학생란에 실렸고, 저자 사후 70년이 지나 퍼블릭 도메인입니다. 본문은 [한국어 위키문헌](https://ko.wikisource.org/wiki/달을_쏘다)에서 가져왔습니다.

제목까지 13문단을 여섯 단락으로 끊었습니다. 제목, 밤과 달빛 든 방, H군의 편지, 우정에 대한 생각, 정원에서 달을 쏘다, 활을 만들다 순입니다.

수정본은 1939년 글을 오늘 표기로 옮긴 시연용입니다(방언과 입말은 손대지 않았습니다).

바뀌는 문단은 11개입니다. 문구 수정이 10개, 마지막 단락을 두 문장으로 나눈 문장 나눔이 1개입니다.

「설문 보기」는 표가 든 인구통계 설문지 두 벌입니다. 최종본에서 표가 하나 늘어, 표 안의 글을 비교하는 모습과 표 개수가 다를 때의 알림을 함께 볼 수 있습니다.

예문 원본은 `public/examples/` 한 곳에 있습니다. 앱이 읽어 가고, 표를 다루는 테스트도 같은 파일을 씁니다.

개발용 표본인 `samples/` 에는 메리 셸리 『프랑켄슈타인』 5장([영어 위키문헌](https://en.wikisource.org/wiki/Frankenstein,_or_the_Modern_Prometheus_(Revised_Edition,_1831)), 1831년 개정판, 퍼블릭 도메인)을 한글과 워드로 각각 저장해 두었습니다. 한국어와 영어, 굵게와 기울임, 라틴 악센트가 섞여 있어 시험 표본으로 씁니다.
